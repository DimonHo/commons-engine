## 一、命题与设计原则

### 1.1 冷启动的根本难题

双边市场的最大难题是冷启动（chicken-and-egg / network cold-start）：

```
劳动者不够多 → 消费者等不到 → 消费者流失 → 劳动者无单 → 劳动者流失 → 崩塌
```

公地引擎的冷启动约束比传统烧钱平台**更紧**：

| 维度 | 资本平台冷启动 | 公地引擎冷启动 |
|------|---------------|---------------|
| 破局工具 | 补贴烧钱（双边） | **禁止烧钱补贴**（无补贴是存在性命题） |
| 劳动者画像 | 全职骑手（追求补贴差价） | 合作社成员（追求长期所有权 + 高分成） |
| 消费者获客 | 优惠券/红包 | 零营销预算（社区/口碑） |
| 风险约束 | 资本可承担试错 | 必须一击中的（资源有限） |

**结论**：公地引擎的冷启动不能复制烧钱 playbook，必须用「地理聚焦 + 组织动员 + 高分成吸引力」组合拳，在最小地理单元（单一社区/商圈）先跑通，再扩张。

### 1.2 设计原则

1. **最小地理单元优先**：不追求「全城覆盖」，先在**一个社区/一个商圈**达到供需密度阈值，再裂变。
2. **先供后求**：劳动者侧先有种子队伍（有组织基础 + 高分成激励），再引入消费者。劳动者的等待成本是冷启动期的最大杀手。
3. **零营销预算**：获客依赖社区组织、口碑、劳动者转介绍——而非广告投放。
4. **量化临界规模**：用 [#50 单位经济](./unit-economics.md) 的盈亏平衡单量（Q_BE）反推所需劳动者数量与消费者单量。
5. **反榨取护栏前置**：冷启动期不放松反榨取约束（见 [RFC-001](../rfcs/0001-anti-exploitation-params.md)）——这正是公地引擎区别于竞品的核心，放松它就失去了存在的理由。

## 二、与单位经济模型（#50）的对接

本策略的所有量化目标都从 [#50](./unit-economics.md) 的盈亏平衡单量推导。

### 2.1 关键参数引用

| 参数 | 值（成都配送假设） | 来源 |
|------|-------------------|------|
| Q_BE_day（志愿期） | **70 单/日** | #50 §4.2 |
| Q_BE_day（含1兼职技术） | 247 单/日 | #50 §4.2 |
| 单均劳动者所得 | ¥17.60 | #50 §5.1 |
| 劳动者正常效率 | 2.5 单/小时 | #50 §5.2 |
| 劳动者日均单量（满负荷） | ~20 单/日（8h × 2.5） | 推导 |

### 2.2 种子劳动者数量估算

**目标**：覆盖 Q_BE_day = 70 单/日 所需的活跃劳动者数量。

```
N_workers_seed = Q_BE_day / Q_per_worker_day
```

| 劳动者效率假设 | Q_per_worker_day | N_workers_seed（覆盖70单/日） |
|---------------|------------------|-------------------------------|
| 新人期（1.5单/h, 4h在线） | 6 单/日 | 12 人 |
| 正常期（2.5单/h, 6h在线） | 15 单/日 | 5 人 |
| 熟练期（3.5单/h, 8h在线） | 28 单/日 | 3 人 |

**保守结论**：冷启动期需 **8–12 名活跃种子劳动者**（含新人期低效冗余），可在单一社区/商圈覆盖 70 单/日的盈亏平衡线。

> **诚实标注**：以上假设劳动者「在线即有单」。冷启动初期单量不足时，劳动者会长时间等单（等单成本侵蚀收入）。这正是 §4 缓冲机制要解决的问题。

### 2.3 消费者单量需求

```
N_consumers_seed = Q_BE_day / Q_per_consumer_week × 7（周复购换算）
```

| 假设 | Q_per_consumer_week | N_consumers_seed（支撑70单/日 = 490单/周） |
|------|---------------------|-------------------------------------------|
| 高频用户（3单/周） | 3 | 163 人 |
| 中频用户（1.5单/周） | 1.5 | 327 人 |
| 低频用户（0.5单/周） | 0.5 | 980 人 |

**结论**：需 **160–330 名活跃种子消费者**（中高频），对应单一社区/商圈的可达规模（一个中型社区 1000–3000 户，渗透率 10–20% 即可达）。

## 三、临界规模定义（量化指标）

「跨过临界规模」不是模糊概念，必须有可观测、可证伪的量化指标。

### 3.1 临界规模判定指标（建议值，需人类/全体大会校准）

| 指标 | 临界值 | 含义 | 决策属性 |
|------|--------|------|----------|
| 高峰时段匹配成功率 | **≥ 80%** | 消费者下单后 3 分钟内有劳动者接单 | 技术可测 |
| 劳动者平均等单时长 | **≤ 8 分钟** | 高峰期劳动者从在线到接到首单的等待 | 技术可测 |
| 消费者平均履约时长 | **≤ 35 分钟** | 下单到送达 | 技术可测 |
| 日均订单量 Q_day | **≥ Q_BE_day（70 单/日，志愿期）** | 跨过盈亏平衡线 | 对接 #50 |
| 劳动者周留存率 | **≥ 80%** | 种子劳动者不流失 | 运营可测 |
| 消费者周复购率 | **≥ 40%** | 首周下单用户次周仍下单 | 运营可测 |

> **判定逻辑**：当以上 6 项指标**连续 7 天同时满足**，则判定「跨过临界规模」，冷启动阶段结束，进入增长期。

### 3.2 未跨过临界规模的应对（防崩塌）

冷启动期最危险的是「指标下滑 → 双边流失 → 崩塌」。预设干预触发器：

| 触发条件 | 干预动作 | 决策属性 |
|----------|----------|----------|
| 匹配成功率连续 3 天 < 60% | **收缩地理范围**（聚焦更小单元，提升密度） | 需人类决定 |
| 劳动者周留存 < 60% | 评估「等单过长」根因，调整种子规模或地理范围 | 运营 |
| Q_day 连续 14 天 < Q_BE_day | 触发 #50 §7 证伪条件复核——调整参数或承认品类/城市不成立 | **需人类决定** |

## 四、种子劳动者招募策略

### 4.1 来源优先级（有组织基础 > 散户）

公地引擎的劳动者是**合作社成员/所有者**，不是零工。招募应优先有组织基础的群体：

| 优先级 | 来源 | 为什么 | 决策属性 |
|--------|------|--------|----------|
| P1 | **现有骑手/司机互助群、行业社群** | 对平台抽成痛点有一手体感，对「合作社」概念接受度高 | 需人类对接 |
| P2 | **工会/劳工 NGO 合作** | 有组织基础、有信任、有集体行动经验 | 需人类决定合作方 |
| P3 | **劳动者转介绍（内推）** | 种子劳动者转介绍同乡/同行，信任度高、留存好 | 可设计内推激励（非金钱：如合作社贡献分记录） |
| P4 | **公开招募** | 兜底，但散户缺乏组织基础，留存风险高 | — |

### 4.2 价值主张（零补贴下靠什么吸引）

不能靠补贴吸引劳动者，必须靠**结构性优势**：

| 价值点 | 公地引擎 | 竞品（美团/滴滴） |
|--------|----------|-------------------|
| 分成比例 | **80%（透明）** | ~60-70%（含隐性扣减） |
| 所有权 | **劳动者是股东，参与分红 + 治理** | 无 |
| 费用透明 | **每笔交易实时公开拆分** | 黑箱 |
| 反榨取护栏 | 评价不挂钩派单、不疲劳派单 | 算法黑箱惩罚 |
| 时薪（正常效率） | **¥44**（#50 §5.2） | ¥25-35（实测） |

**招募话术核心**：「同样跑单，到手多 20%，且你是老板之一」。

### 4.3 新人保护机制（对接 RFC-001）

冷启动期大量新人进入，RFC-001 的 `newcomerProtectionDays=7` 必须生效：

- 新人注册 7 天内享受**优先匹配**（匹配引擎权重加成）
- 新人不因低初始评分被降权（`ratingNotLinkedToDispatch=true`，不可篡改）
- 新人首单有「保底」（若 30 分钟无单，系统提示附近同业老手带教——**需人类设计带教机制**）

> **护栏校验**：冷启动期的「优先匹配新人」是否违反反榨取原则？——**不违反**。反榨取是「不压低工资/不疲劳派单」，新人优先是「扶上马」，方向相反。但优先匹配的权重参数需公开可审计（RFC-001 §6）。

## 五、消费者冷启动策略（零营销）

### 5.1 获客路径（社区/口碑优先）

| 路径 | 机制 | 成本 | 预期转化 |
|------|------|------|----------|
| **社区组织合作** | 与社区居委会/业委会/物业合作，在单一社区内推广 | 极低（人力） | 高（信任传递） |
| **劳动者转介绍** | 种子劳动者向其服务过的消费者推荐 | ¥0 | 中高 |
| **在地组织/NGO** | 与本地劳工/社区组织联合推广 | 极低 | 中 |
| **口碑/复购** | 首批用户体验好 → 自发传播 | ¥0 | 长期最优 |

### 5.2 首批消费者画像

公地引擎的首批消费者不是「价格敏感型羊毛党」（那是补贴平台的用户），而是：

- **价值认同型**：认同「支持劳动者合作社」理念（社区组织动员触达）
- **关系型**：与种子劳动者有既有信任（同社区、转介绍）
- **品质敏感型**：更看重服务质量与透明度，而非最低价

**预期**：首批 160-330 名消费者中，价值认同型 + 关系型应占 **60%+**——他们是留存的主力，也是口碑传播的种子。

### 5.3 不做的事（反 playbook）

- ❌ **不发优惠券/红包**（违背无补贴命题）
- ❌ **不投广告**（零营销预算）
- ❌ **不烧钱买量**（资源有限，且买来的用户是羊毛党，留存差）

| 阶段 | 时长（建议） | 目标 | 关键动作 | 决策属性 |
|------|-------------|------|----------|----------|
| **第0阶段：组织动员** | 2-4 周 | 招募 8-12 名种子劳动者 | 对接互助群/工会/NGO，宣讲合作社模式 | **需人类执行** |
| **第1阶段：预热点** | 1-2 周 | 锁定 1 个社区/商圈，消费者预热 | 社区组织合作，首批消费者注册 | **需人类执行** |
| **第2阶段：开城** | Day 0 | 正式上线，种子双边同步启动 | 劳动者到位 + 消费者下单 | 技术就绪（阶段1已完成 ✅） |

**总冷启动周期估计**：**2-3 个月**（从组织动员到跨过临界规模）。

## 七、与反榨取护栏的兼容性校验

#49 acceptance criteria 要求「反榨取护栏在冷启动期的应用」。逐项校验：

| RFC-001 护栏 | 冷启动期是否生效 | 说明 |
|--------------|-----------------|------|
| `maxPlatformFeeRate ≤ 0.15` | ✅ 生效 | 冷启动也不提高抽成（否则违背存在性命题） |
| `transparentFeeBreakdown = true` | ✅ 生效（不可篡改） | 冷启动正是建立信任的关键期 |
| `ratingNotLinkedToDispatch = true` | ✅ 生效（不可篡改） | 新人低评分不降权 |
| `newcomerProtectionDays = 7` | ✅ 生效 | 冷启动期新人占比高，此护栏至关重要 |
| `maxMatchRadiusMeters ≤ 5000` | ✅ 生效 | 冷启动聚焦小地理单元，半径本就小 |
| `maxDailyActiveHours ≤ 12` | ✅ 生效（全体大会定终值） | 不因「缺人」而让少数劳动者过劳 |
| `minBreakBetweenOrdersMin` | ✅ 生效（全体大会定终值） | 同上 |

**结论**：冷启动期**不放松任何反榨取护栏**。这正是公地引擎的差异化——竞品在冷启动期往往用「高强度派单 + 低保障」压榨少数劳动者，公地引擎明确拒绝此路径。代价是冷启动需要更多种子劳动者（而非让少数人超负荷），这已反映在 §4.2 的 N_workers_seed 估算中。

## 十一、结论（初步，待实证）

1. **冷启动可行，但路径窄**：在成都配送场景下，8-12 名种子劳动者 + 160-330 名种子消费者，聚焦单一社区/商圈，2-3 个月可达临界规模（70 单/日盈亏平衡线）。可行，但容错空间小。
2. **组织动员是关键**：公地引擎不能用钱破局，只能用**组织基础 + 高分成吸引力 + 合作社所有权**破局。种子劳动者必须来自有组织基础的群体（互助群/工会/NGO），而非散户。
3. **反榨取护栏是特色不是包袱**：冷启动期不放松任何护栏，这恰恰是最强的差异化——竞品做不到，公地引擎能做到。
4. **地理聚焦 > 全城铺开**：先在一个社区跑通密度，再裂变。贪大是冷启动最常见的死法。
5. **须实证证伪**：以上为桌面推演，冷启动后用真实数据校准所有阈值。若连续 14 天 Q_day < Q_BE_day 且干预无效，须诚实面对证伪（对接 #50 §7）。
